# Orchestrator Agent API Documentation

Base URL: `/`

---

## Agent Registry

### POST /agents/add

Register a new agent dynamically.

- Headers:
  - `x-admin-token`: Admin token for authorization.
- Request Body (JSON):
  ```json
  {
    "name": "string",
    "host": "string",
    "port": int
  }
  ```
- Responses:
  - 200: Agent registered successfully
    ```json
    { "message": "Agent registered successfully" }
    ```
  - 400: Validation or duplicate agent errors
  - 403: Unauthorized access

---

### GET /agents/active

Get a list of currently active and healthy agents.

- Response Body:
  ```json
  [
    {
      "id": int,
      "name": "string",
      "host": "string",
      "port": int,
      "is_active": true,
      "is_healthy": true,
      "agent_card": {...},
      "created_at": "datetime",
      "last_health_check": "datetime"
    }
    // ...
  ]
  ```

---

### GET /agents/total_agents

Get a list of all registered agents irrespective of status.

- Response: Same as `/agents/active` but includes all agents.

---

### DELETE /agents/{agent_name}

Deactivate an agent (soft delete).

- Headers:
  - `x-admin-token`: Admin token for authorization.
- Path Parameters:
  - `agent_name`: Name of the agent to deactivate.
- Response:
  ```json
  { "message": "Agent '{agent_name}' deactivated successfully" }
  ```
- 404 if agent not found.

---

### PATCH /agents/{agent_name}/activate

Activate a previously deactivated agent.

- Headers:
  - `x-admin-token`: Admin token for authorization.
- Path Parameters:
  - `agent_name`: Name of agent to activate.
- Response:
  ```json
  { "message": "Agent '{agent_name}' activated successfully" }
  ```

---

### DELETE /agents/agent_registry/{agent_name}

Delete an agent permanently from the registry and orchestrator.

- Headers:
  - `x-admin-token`: Admin token for authorization.
- Path Parameters:
  - `agent_name`: Name of agent to delete.
- Response:
  ```json
  { "message": "Agent '{agent_name}' deleted permanently" }
  ```
- 404 if agent not found.

## Files

### GET /files/{tenant_id}/{user_id}/{session_id}/{file_id}/{filename}

Download a file with signed URL verification.

- Query Parameters:
  - `exp` (int): Expiry timestamp
  - `sig` (string): Signature for URL validation
- Path Parameters:
  - `tenant_id`, `user_id`, `session_id`, `file_id`, `filename`
- Response:
  - File served as `application/octet-stream`
- 403 if signature invalid
- 404 if file not found

## Run Agent

### POST /run/

Run an agent with a prompt and session id.

- Request Body (JSON):
  ```json
  {
    "prompt": "string",
    "session_id": "string" // default is "default-session"
  }
  ```
- Response Body:
  ```json
  {
    "response": "string"  // The response text generated by the agent
  }
  ```
- 500 on internal server error.

---

## File Upload

### POST /upload/

Upload files to user-scoped storage path.

- Request: `multipart/form-data`
  - `files`: List of files to upload
  - `session_id`: string form field
- Response:
  ```json
  {
    "status": "success",
    "user_id": "string",
    "tenant_id": "string",
    "session_id": "string",
    "file_id": "string",
    "file_count": int,
    "files": [
      {
        "file_name": "string",
        "file_path": "string",
        "file_size": int,
        "file_url": "signed url string"
      }
    ]
  }
  ```
- 401 if authentication info missing or invalid
- 500 on server error

## WebSocket Endpoint

### WebSocket `/ws/{session_id}`

Establish a WebSocket connection for bidirectional real-time communication with agents.

- URL Params:
  - `session_id` (string): ID of the session to connect to.
  - `user_id` (string, optional): User ID (default set as a constant).
- The server uses `WebSocketHandler` to handle incoming/outgoing messages.
- Used for streaming responses and live interaction with agents.
